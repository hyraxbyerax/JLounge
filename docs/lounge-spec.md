# 라운지 기능 명세

> 개발 중 결정이 바뀌면 이 문서를 먼저 고친다. [선택] 표시는 필수 기능 완성 후에 한다.

## 1. 사용자

| 기능 | 로그인 사용자 | 게스트 |
| --- | --- | --- |
| 방 만들기·방장, 채팅, 음악 신청, 게임 참가 | 가능 | 가능 |
| 공개방 입장, 코드·링크 입장 | 가능 | 가능 |
| 친구 추가·초대, 친구 초대로 입장(비밀번호 생략) | 가능 | 불가 |
| 활동 상태 표시 | 가능 | 불가 |
| 캠퍼스 플래너 (일정·시간표, 스케줄러 팀원 작품) | 가능 | 불가 → 로그인 화면으로 안내 (서버도 403으로 막음) |

- 게스트: 서버가 `guest_` + 무작위 문자열로 임시 ID와 닉네임을 발급. 접속 종료 시 소멸.
- 로그인(회원): 이메일 + 비밀번호(8자 이상) + 닉네임(20자까지)으로 가입. 비밀번호는 scrypt 해시로 저장. 로그인은 새로고침·재방문에도 7일 유지되고, 라운지와 캠퍼스 플래너가 같은 로그인을 쓴다. 로그인 버튼은 메인 화면 오른쪽 위와 캠퍼스 플래너 입구 두 곳. AWS를 연결할 때 Cognito로 바꾼다 (지금 가입한 계정은 옮겨가지 않음).
- 게스트로 방에 있다가 로그인하면(방 안 [로그인] 버튼), 로그인한 ID로 **같은 방에 자동 재입장**시킨다. 입장 순서·방장 자리를 그대로 이어받고, 채팅에 "○○님이 로그인해서 △△님이 됐어요"가 남는다. 비밀번호·자물쇠는 다시 묻지 않는다 (이미 들어와 있던 사람이므로).

## 2. 로비와 방 목록

- 로비에는 **공개방만** 표시. 비공개방은 목록에 나오지 않는다.
- 잠긴 방(자물쇠)도 목록에 남되 자물쇠 아이콘 표시. 누르면 "방장이 입장을 잠근 방이에요" 안내.
- 정렬: 입장 가능한 방 위, 잠긴 방 아래. 필터: "입장 가능한 방만 보기".
- 방 카드: 방 이름, 현재/최대 인원, 진행 중인 게임, 재생 중인 곡, 자물쇠 아이콘.
- 로비에서 방 코드 입력, 새 방 만들기.

## 3. 방 만들기와 설정

- 로그인·게스트 모두 생성 가능. 만든 사람이 방장.
- 생성 시 6자리 방 코드 + 초대 링크(`/room/{코드}`) 발급. 방이 비면 코드 만료.
- 방 코드는 방 안 방 이름 옆에 항상 보이고, 누르면 복사된다. [초대]는 초대 링크를 복사한다.

| 설정 | 값 | 규칙 |
| --- | --- | --- |
| 공개 여부 | 공개 / 비공개 | 공개방만 로비에 표시 |
| 비밀번호 | 선택 | 해시로 저장 (bcrypt 등) |
| 자물쇠 | 켜기 / 끄기 | 생성 시 옵션, 방 안에서 방장이 언제든 변경 |
| 최대 인원 | 숫자 | 방장이 변경 가능, 현재 인원보다 작게 불가 |

## 4. 입장 규칙

| 입장 방식 | 대상 | 비밀번호 | 잠긴 방 |
| --- | --- | --- | --- |
| 로비 목록 | 공개방 | 설정된 경우 입력 | 불가 |
| 방 코드 / 초대 링크 | 공개·비공개방 | 입력 | 불가 |
| 친구 초대 | 로그인 사용자 | 생략 | **방장이 보낸 초대만** 가능 |

- 비밀번호 5회 실패 → 10분 동안 그 방 입장 시도 잠금 (로그인: 계정 기준 / 게스트: 세션·IP 기준).
- 강퇴된 사용자는 그 방에 재입장 불가.
- 최대 인원이면 입장 불가.
- 게임 진행 중에도 입장 가능, 다음 판부터 참가.

## 5. 방장 권한

- 방장 위임, 강퇴, 초대, 방 설정 변경(공개 여부·비밀번호·자물쇠·최대 인원), 게임 선택·시작, 음악 관리 명령어.
- 방장이 나가면 **가장 오래 있던 사용자**에게 자동 위임. 마지막 사용자가 나가면 방 삭제. 연습 상대는 사용자로 치지 않는다 (방장이 될 수 없고, 사람이 모두 나가면 방이 삭제된다).
- 위임·강퇴는 참가자 목록에서 (방장에게만 보임). 강퇴는 "○○님을 내보낼까요? 다시 들어올 수 없어요" 확인 창을 거친다. 연습 상대를 내보내면 재입장 차단 없이 나가기만 한다.
- 탭을 닫거나 연결이 끊긴 사람은 잠시(약 5초) 기다렸다가 나간 것으로 처리한다 (새로고침하면 그대로 남는다). 서버가 갑자기 꺼진 경우에도 30초 안에 정리된다.

## 6. 채팅

- 같은 방 실시간 채팅. 채팅창이 명령어 입력창을 겸한다.
- `/`로 시작하는 메시지는 명령어로 처리하고 채팅에 표시하지 않는다. 권한이 없으면 본인에게만 안내.
- 시스템 메시지: 입장·퇴장, 방장 변경, 곡 변경, 게임 시작·종료.
- 메시지 길이 제한(200자).
- 새로 들어온 사람은 **들어온 뒤의 채팅만** 본다. 연결이 잠깐 끊겼다 돌아오면 그 사이 놓친 메시지를 다시 받는다 (2026-11-25 결정).
- **도배 방지 (평소)**: 한 사람당 5초에 5개까지. 넘으면 본인에게만 "잠깐 천천히 보내주세요" (서버에서 확인, 2026-11-25 결정).
- **희노애락 이모지**: 입력창 왼쪽 😊 버튼을 누르면 위로 😄(기쁨) 😠(화남) 😢(슬픔) 🤣(즐거움) 판이 펼쳐진다 (바깥을 누르거나 Esc로 닫힘, 보내면 닫힘). **두 번 누르면 그 이모지 하나만 바로 보낸다**(글과 섞지 않음, 한 번 누르면 아무 일 없음, 키보드는 Enter). 이모지만 보낸 메시지는 말풍선 없이 크게 보인다. 캐치마인드 진행 중에는 채팅 3초 제한이 똑같이 적용된다.
- **채팅 3초 제한 (게임 라운드 진행 중, 이번 판 참가자에게만)**: 채팅을 한 번 보내면 3초 동안 다음 채팅을 보낼 수 없다 (정답 연타·도배 방지). 평소 채팅과 게임 대기·결과·정답 공개 중에는 제한 없음. 입력은 미리 해둘 수 있고, 보내기 버튼에 남은 초를 보여준다. 명령어(`/`)는 제한하지 않는다. 서버에서도 같은 규칙으로 확인한다. (캐치마인드는 채팅으로 맞히는 게임이라 적용)

## 7. 음악 같이 듣기

방마다 재생 상태 하나와 대기큐 하나. 방 안의 모두가 같은 곡을 같은 타이밍에 듣는다.

### 동작
- 유튜브 검색으로 곡 신청. 재생 중인 곡이 없으면 바로 재생, 있으면 대기큐 맨 뒤.
- 검색: 서버가 유튜브 Data API로 찾는다(`GET /api/lounge/music/search?q=`). [검색]을 눌렀을 때만 검색하고, 같은 검색어는 6시간 동안 Redis(`ytsearch:`)에 저장해 재사용한다. 한 사람당 1분에 10번까지. 생방송(끝나지 않음)과 퍼가기 금지 영상은 결과에서 뺀다. `YOUTUBE_API_KEY`가 없으면 예시 곡만 나온다.
- 곡이 끝나면 대기큐 맨 앞 곡 재생. **이전 곡 기능 없음** (끝난 곡은 큐에서 제거).
- 대기큐에 제목과 신청자 닉네임 표시. 신청자가 나가도 곡은 남는다.
- 1인당 대기큐 최대 3곡, 같은 곡 중복 신청 불가.

### 권한
- 일반 사용자: 신청, **본인이 신청한 곡 중 대기큐에 있는 곡**만 취소.
- 방장: 위 + 명령어.

| 명령어 | 동작 |
| --- | --- |
| `/skip` | 현재 곡 끝내고 다음 곡 |
| `/pause` | 일시정지 (위치 유지) |
| `/resume` | 멈춘 위치부터 재생 |
| `/stop` | 현재 곡 종료, 대기큐 유지, 자동 재생 안 함 |
| `/remove {번호}` | 대기큐에서 삭제 |
| `/move {번호} {위치}` | 대기큐 순서 변경 |
| `/clear` | 대기큐 비우기 |

### 동기화
- 서버가 `현재 곡 ID, 제목, 길이, 시작 시각, 일시정지 위치, 상태`를 저장. 브라우저는 `현재 시각 − 시작 시각`으로 위치 계산.
- 접속 시 서버 시간을 받아 시계 차이 보정 (`time:sync`).
- 일시정지: 멈춘 위치 저장 / 재개: `새 시작 시각 = 현재 시각 − 멈춘 위치`.
- 브라우저는 주기적으로 오차를 확인해 2~3초 이상 어긋나면 다시 맞춘다 (광고 등).
- **다음 곡 전환은 서버가 담당**한다. 신청 시 곡 길이를 받아두고, 곡이 끝날 시점에 전환. 브라우저의 "끝났음" 신호로 넘기지 않는다.
- 서버가 여러 대여도 한 번만 넘어가도록 "현재 곡이 아직 이 곡일 때만 다음으로"를 원자적으로 처리.
- 서버 타이머는 서버 메모리에 의존하지 않게 설계한다 (예: Redis에 "곡 종료 예정 시각"을 저장하고 주기적으로 확인, 어느 서버가 처리해도 되게).
- 재생 불가 영상: 신청 시 서버가 유튜브에서 영상을 확인한다 (없음·퍼가기 금지·생방송이면 거절, 제목·길이는 서버가 받은 값을 쓴다). 재생 중 브라우저가 오류를 알리면, 지금 곡이 아직 그 곡일 때만 다음 곡으로 (여럿이 알려도 한 번).
- 유튜브 공식 IFrame 플레이어를 화면에 보이게 두고 재생 (약관 준수).
  - **예외 (팀 결정, 2026-10-29)**: 게임이 열려 있는 동안(시작 대기·진행·결과)에는 영상을 화면 밖으로 빼고 소리만 계속 낸다. 음악은 위쪽 미니 바로 보여주고, 게임을 닫으면 영상이 다시 보인다. 유튜브 약관(플레이어 200×200 이상 표시)과 다른 점을 알고 정한 것이다.
  - **영상 안 조작 막기 (팀 결정, 2026-10-29)**: 모두가 같은 위치를 들어야 하므로 유튜브 자체 버튼·키보드 조작을 끄고, 영상 위를 투명하게 덮어 클릭으로 멈추지 못하게 한다. 영상은 고정된 크기로만 보고(전체 화면 없음), 영상 위에서는 우리 버튼으로 **내 음량 조절만** 할 수 있다. 방장은 여기에 **일시정지·재생 버튼**이 더 있다(모두에게 적용). 다음 곡 등 나머지는 음악 바 버튼이나 명령어로 한다. 플레이어를 덮는 것도 유튜브 약관이 권하지 않는 방식이다.
- 음악 조작 (기능 하나당 버튼 하나):
  - 영상 위: 내 음량(모두), 일시정지·재생(방장)
  - TV 아래 리모컨: 곡 정보, 재생 위치, 다음 곡(방장), 대기열, 곡 신청. **방장은 진행 막대를 끌어 재생 위치를 옮길 수 있다** (서버가 모두에게 같은 위치로 맞춘다). 진행 막대와 시간은 서버 기준 위치라 모두에게 같게 보인다
  - 게임 중 미니 바: 일시정지·재생·다음 곡(방장), 내 소리 끄기, 대기열, 곡 신청
  - 일시정지·재개는 채팅에 시스템 메시지를 남기지 않는다 (TV의 일시정지 화면으로 충분).

## 8. 미니게임

- 채팅으로 정하고 방장이 선택·시작. 게임 중에도 채팅·음악 계속.
- 방장은 진행 중인 게임을 언제든 강제로 끝낼 수 있다: 게임 화면 타이머 옆 [게임 끝내기] (확인 창) 또는 `/endgame` 명령어 (방장이 아니면 본인에게만 안내).
- **모든 게임은 공통 틀**을 구현한다: 단계 `waiting → playing → result → waiting`, 공통 상태(게임 종류, 단계, 참가자, 점수, 라운드)는 같은 형식으로 Redis에.
- 판정은 서버에서. 플레이어별 숨김 정보는 해당 플레이어에게만 (`game:private`).
- 진행 중에 들어온 사용자는 다음 판부터 참가.
- 게임: **캐치마인드 하나** (2026-11-25 사용자 결정: 초성 퀴즈는 빼고, 2인용 블록 게임은 디자인·이름 저작권 문제로 만들지 않음). 방장이 [게임]을 누르면 고르는 창 없이 바로 캐치마인드가 열린다. 나중에 게임을 더하려면 공통 틀(`packages/shared/src/games/`)에 같은 모양으로 넣는다.
- 게임이 열려 있는 동안 방 안의 모든 사람이 같은 게임 화면을 본다. 게임 중 들어온 사람은 화면은 보지만 이번 판 점수판에는 없고, 채팅은 평범하게 한다.
- 시간 흐름(라운드 끝·힌트·다음 라운드)은 서버가 Redis에 "다음 확인 시각"을 두고 0.5초마다 확인한다 (어느 서버가 처리해도 되고, 저장은 판 번호를 비교해 한 번만 성공).
- 그리던 사람이 방을 나가면 그 라운드는 바로 끝나고 정답을 공개한다. 나간 사람의 그릴 차례는 건너뛴다.

### 캐치마인드 규칙
- 한 판 6라운드. 참가자가 돌아가며 그린다 (2명이면 각 3번).
- 라운드 80초. 남은 시간이 40초 이하가 되면 맞히는 사람에게 첫 글자를 힌트로 보여준다.
- 정답은 채팅으로 입력한다 (띄어쓰기·대소문자 무시). 정답 메시지는 채팅에 올리지 않고 "○○님이 정답을 맞혔어요"로 알린다.
- 점수: 맞힌 사람 10점 + 빨리 맞힐수록 최대 10점 보너스(남은 시간 비율), 그린 사람은 맞힌 사람 한 명마다 5점.
- 그리는 사람을 뺀 모두가 맞히면 라운드를 바로 끝낸다. 라운드가 끝나면 4초 동안 정답을 공개하고 다음 라운드로.
- 제시어는 그리는 사람(과 이미 맞힌 사람)에게만 보낸다. 그리는 사람·이미 맞힌 사람이 정답이 들어간 채팅을 쓰면 막는다.
- 판이 끝나면 순위를 보여주고(같은 점수는 같은 등수), 방장이 "한 판 더" 또는 "게임 끝내기"를 고른다.
- 그림판: 800×500 좌표로 저장, 색 7가지·굵기 3단계·지우개·되돌리기·전부 지우기. 한 획(누르고 뗄 때까지)씩 서버를 거쳐 모두에게 간다. 그리는 사람만 그릴 수 있다 (서버가 확인).

### 캐치마인드 제시어와 주제 (2026-11-25)
- 제시어는 주제별 목록(`packages/shared/src/games/words.ts`)에서 무작위로 고르고, 한 판 안에서는 겹치지 않는다.
- 주제: **전체** / 동물 / 음식 / 물건 / 자연·장소 / 탈것·운동 / **캠퍼스**(도서관, 학식, 조별과제, 수강신청 등). 주제마다 25~31개, 전체 약 170개.
- 방장이 게임 대기·결과 화면에서 주제를 고른다 (기본: 전체). 바꾸면 모두에게 보이고 채팅에 알린다. 진행 중에는 바꿀 수 없고, "한 판 더"는 같은 주제로 한다.
- 연습 상대가 그릴 차례면 그 주제 안에서 그림이 있는 단어를 고르고, 없으면(예: 캠퍼스) 그릴 수 있는 아무 단어로 그린다.

### 연습 상대 (2026-11-25 결정: 방장이 불렀을 때만)
- 방장이 [연습 상대 부르기]를 누르면 가상 사람 1명("새벽코딩")이 서버 쪽 참가자로 들어온다. 모두에게 보이고, 채팅에 가끔 대답한다.
- 게임에도 참가자로 낀다 (서버가 움직인다). 캐치마인드에서 그릴 차례에는 미리 만든 그림을 20초에 걸쳐 한 획씩 그리고, 맞히는 차례에는 5~9초마다 맞혀보며 시간이 지날수록 맞힐 확률이 오른다 (처음엔 엉뚱한 오답).
- 방장이 참가자 목록에서 내보낼 수 있다. 사람이 모두 나가면 방과 함께 사라진다.

## 9. 친구와 활동 상태 (로그인 사용자)

**친구 현황판** (2026-11-25 사용자 요청: 리그 오브 레전드 친구 메신저처럼 오른쪽에 쫙 펼쳐서)
- 넓은 화면(1100px 이상)에서는 메인·로비 **오른쪽에 늘 펼쳐 둔다.** 방 안(게임 중 포함)은 칸이 셋이면 정신없어서, 오른쪽 한 칸을 **[방 채팅 | 친구] 탭**으로 나눈다 (2026-11-25 사용자 결정). 친구 탭에는 접속 중인 친구 수와 안 읽은 메시지 수가 보인다. [»]로 접으면 얇은 띠(접속 중인 친구 수·안 읽은 메시지 수)만 남고, 누르면 다시 펼친다 (브라우저마다 기억).
- 좁은 화면(휴대폰 등)에서는 [친구] 버튼으로 오른쪽에서 밀려 나오는 서랍으로 연다.
- 캠퍼스 플래너는 오른쪽 "친구" 칸에 같은 현황판을 넣는다.
- 게스트에게는 "로그인하면 친구와 대화할 수 있어요" + [로그인] (방 안에서도 그 자리에서 로그인).
- 목록: 맨 위 친구 추가(닉네임·친구 코드) → 받은 요청(수락·거절) → **접속 중** 친구 → 오프라인 친구. 친구마다 접속 점, 있는 방·활동, 안 읽은 메시지 수. 맨 아래 "내 친구 코드·설정"(코드 복사, 공개 범위, 보낸 요청, 차단 목록).

**1:1 대화** (친구끼리만)
- 친구를 누르면 현황판 안에서 대화가 열린다. 위에 [따라가기]·[이 방에 초대], [⋯]에 친구 끊기·차단.
- 대화는 서버(PostgreSQL)에 저장해서 나중에 열어도 보인다. 최근 50개씩, 위로 "이전 대화 더 보기". 한 메시지 500자, 5초에 5개까지.
- 새 메시지는 실시간으로 온다. 그 대화를 보고 있지 않으면 화면 아래 짧은 알림("💬 닉네임: 내용")과 친구 옆 안 읽은 수. 대화를 열면 읽음.
- 친구가 아니면(끊기·차단 포함) 보내지도 읽지도 못한다.

**친구 요청**
- 닉네임 또는 친구 코드(8자리, 가입 때 발급, 친구 창에서 복사)로 요청. 같은 닉네임이 여러 명이면 "친구 코드로 요청해주세요"로 안내한다.
- 방 안 참가자 목록에서 회원 옆 [친구 요청] (게스트·연습 상대·이미 친구·이미 요청한 사람에게는 안 보임).
- 하루 **20번**까지 (2026-11-25 결정, 사용자 확인 필요). 서로 요청하면 바로 친구가 된다.
- 받은 요청은 수락·거절, 보낸 요청은 취소. 친구는 끊기·차단.
- 요청 알림: 접속 중이면 실시간 알림(토스트), 아니면 다음 접속 때 친구 창 "받은 요청"에.
- 나·게스트·없는 회원에게는 보낼 수 없다.

**차단**
- 차단하면 친구·요청이 사라지고, 서로 요청을 보낼 수 없다. 차단당한 사람은 "친구 요청을 보낼 수 없어요"만 보고 차단 사실은 모른다.
- 차단 목록에서 [차단 풀기].

**초대·따라가기**
- 지금 방에 있으면 접속 중인 친구 옆에 [초대]. 받은 사람은 화면 위 배너에서 [들어가기]로 **비밀번호 없이** 입장. 초대는 10분 유효, 한 번 쓰면 사라진다.
- 자물쇠 걸린 방은 **방장이 보낸 초대만** 통한다. 정원·강퇴 규칙은 그대로.
- [따라가기]: 친구가 있는 방으로 가는 일반 입장 (비밀번호·자물쇠 규칙 그대로).

**활동 상태**
- 공개 범위: `all`(온라인 + 방·활동) / `online`(온라인만) / `hidden`(오프라인으로 보임, 따라가기 불가). **서버에서 걸러서** 보낸다. 친구 창에서 바꾼다.
- 활동: "라운지에서 쉬는 중" 또는 "캐치마인드 중" (게임 진행 중일 때).
- 브라우저가 20초마다(방·게임이 바뀔 때도) `presence:heartbeat`를 보내고, 60초 동안 없거나 모든 탭을 닫으면 오프라인. 상태가 바뀌면 친구들에게 `presence:update`로 바로 알린다.
