# 개발 순서

> 위에서부터 한 단계씩 진행한다. 각 단계가 끝나면 사용자가 직접 실행해서 확인할 수 있어야 한다. 끝난 항목은 `[x]`로 체크한다.

## 프로토타입 (선택, 0단계 전에)
- [ ] 서버 없이 가짜 데이터로 로비(창문)와 방 안 화면만 만들어 디자인 확인 → 확정되면 0단계로

## 0단계 · 프로젝트 뼈대
- [x] npm workspaces 모노레포 (`apps/web`, `apps/server`), TypeScript·ESLint·Prettier·Vitest 설정
- [x] `docker-compose.yml` (Valkey 8, PostgreSQL 18), `.env.example`, `config.ts`, `.nvmrc`(24)
- [x] 서버: Express + Socket.IO + Redis 어댑터, `GET /health`, SIGTERM 종료 처리, JSON 로그 (SIGTERM은 Windows에서 확인 불가 → 5단계 Docker 이미지에서 확인)
- [x] DB 마이그레이션 도구와 `users` 테이블
- [x] 디자인 토큰 `tokens.css` (밤·낮 모드, SUIT·고운바탕 글꼴) — `docs/design.md` 기준
- [x] 화면: 메인(① 방 만들기 ② 스케줄 관리 "준비 중"), 공통 레이아웃, 소켓 클라이언트(자동 재접속)
- [x] `AuthProvider` 인터페이스 + 로컬 개발용 구현 (게스트 토큰, 간단한 로컬 로그인)

## 1단계 · 방과 채팅
- [ ] 방 만들기 (공개/비공개, 비밀번호, 자물쇠, 최대 인원), 방 코드·초대 링크
- [ ] 로비 목록 (공개방, 자물쇠 표시, 정렬, 필터)
- [ ] 입장 규칙 (비밀번호, 5회 실패 10분 잠금, 인원 초과, 잠금)
- [ ] 실시간 채팅, 시스템 메시지, 도배 방지
- [ ] 방장 권한 (위임, 강퇴·재입장 차단, 설정 변경, 자동 위임, 빈 방 삭제)
- [ ] **다중 서버 확인**: `docker compose --profile multi up`으로 서버 2대에서 같은 방 채팅이 되는지

## 2단계 · 음악 같이 듣기
- [x] `MusicSearchProvider` (가짜 구현 → 유튜브 API 구현, 검색 결과 Redis 캐시)
- [ ] 신청·대기큐·본인 곡 취소, 1인당 제한, 중복 방지
- [ ] 재생 동기화 (서버 시간 보정, 시작 시각 기반 위치 계산, 오차 보정)
- [ ] 서버 주도 다음 곡 전환 (원자적 처리, 서버 메모리 비의존)
- [ ] 방장 명령어 (`/skip` `/pause` `/resume` `/stop` `/remove` `/move` `/clear`)
- [ ] **다중 서버 확인**: 서버 2대에서 곡이 한 번만 넘어가는지

## 3단계 · 미니게임

- [ ] 첫 게임: 캐치마인드 (그림 획 동기화, 제시어 숨김, 정답 판정)
